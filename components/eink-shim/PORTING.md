# Local Lineage 21 compiler adaptation

This copy starts at go7-lineage/eink-shim commit `70e894fd48e0a2c27e94ca6555235fc792eb91b5`, whose target is the monochrome Go7. The upstream README remains the description of that reference. Local changes adapt its syntax and standard-library calls to Lineage 21 Android Rust 1.75 / edition 2021. They retain pointer identities, the commit lock lifetime, checked buffer geometry, protocol layouts, symbol names and panic-abort behavior. The current diff is captured in `preparation/eink-shim-rust175.patch` at the project root.

These are compiler-compatibility changes. Refresh mode numbers, panel geometry, color handling, I/O paths and policy remain the upstream monochrome behavior. This component is not enabled by a GoColor7_2 product and must not be described as a color-model port or an installable image. Existing unit tests cover host-side algorithms and layouts; they cannot validate the actual panel, stock composer ABI, GPU fences, waveform selection or device policy.

`tools/build-host/check_eink_component.py` runs the upstream tests with the manifest-selected Linux Rust 1.75 compiler, checks the Android ARM64 target and attempts the shared-library link with manifest-selected Clang 18 and verified official API 30 stubs. The dependency archive is checked against the pinned upstream lock checksum. The checker uses a temporary path override for that same libc version; source and dependency binds are read-only and the container has no network or device access. Result and artifact hashes are in `work/eink-rust175-compatibility-2026-11-11.json`.

Remaining integration includes exact color refresh ABI review, a GoColor7_2 product, complete Android build, composer loading, SELinux/linker compatibility and approved hardware testing. The inherited `vendor: true` packaging cannot insert a new library into a byte-identical stock vendor image: retaining stock HAL binaries and adding a hook would require an explicitly reviewed derivative vendor image or another qualified loading design. No stock image was modified by this adaptation.

## Initial color profile

The optional Cargo `color-panel` feature now selects kernel AUTO waveform 255, flags 0, no motion-triggered A2 and no frame cutting by default. Explicit legacy modes remain available. A new burst-policy test checks that the color default keeps its quality mode during motion; all 70 host tests and the Android ARM64 link passed. The feature has not been run on the panel. The first vendor derivative packages the resulting library and preserves the original composer code, file permissions and labels. Whole-platform compatibility and hardware behavior remain unqualified.
