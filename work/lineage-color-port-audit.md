# LineageOS starting-point audit for GoColor7_2

Checked **2026-11-11**, using current repository metadata, pinned source, and official Android documentation. This audit performed **no device/USB access, firmware write, EDL action, full Android checkout, or build**. Reference source was read as data; its scripts and programs were not executed. `git apply --check` and patch application were used only on disposable copies of individual upstream source files.

## Result and recommended first target

**No compatible LineageOS image or reproducible exact-model build has been established for the BOOX Go Color 7 Gen II (`GoColor7_2`).** The public `go7-lineage` work is a useful, fairly complete **monochrome Go 7 porting reference**, not a color-model release. Its device/vendor/E Ink/frontlight release APIs were all empty; the device repository had no Actions runs. [Device source](https://github.com/go7-lineage/android_device_onyx_Go7/tree/a446be505809e1ad8bc99814bc6e8b3bfd37ca10), [device releases](https://api.github.com/repos/go7-lineage/android_device_onyx_Go7/releases), [vendor releases](https://api.github.com/repos/go7-lineage/android_vendor_onyx_Go7/releases), [shim releases](https://api.github.com/repos/go7-lineage/eink-shim/releases), [frontlight releases](https://api.github.com/repos/go7-lineage/frontlightd/releases), [device Actions](https://api.github.com/repos/go7-lineage/android_device_onyx_Go7/actions/runs?per_page=10).

**Engineering recommendation:** first develop an **Android 13 / LineageOS 20.0 bring-up target**, preserving the exact-model stock kernel, DTB/DTBO, firmware, color waveform, vendor/display assets and hardware configuration as far as possible. This minimizes the initial change from the known Android 13 system / Android 11 VNDK 30 vendor combination. Use the pinned Go 7 tree to guide device integration and E Ink reverse engineering. This is an inference from the observed baseline and source differences, **not an already-working Lineage 20 port**. Lineage 20's current manifest selects Android 13 and still includes VNDK 30; the only public Go 7 branch is 24.0, so its newer module names, APIs, build definitions, framework changes and SELinux policy require deliberate adaptation. [Local device inventory](device-inventory-2026-11-11.json), [Lineage 20 manifest](https://github.com/LineageOS/android/blob/788664462cc7739a878b3f0fc89af570dc3c14ae/default.xml), [Go 7 branches](https://api.github.com/repos/go7-lineage/android_device_onyx_Go7/branches).

Keep **LineageOS 24.0 / Android 17** as a separate experimental source path. It has the strongest existing Go 7 code reuse and its published patches pass the static context check below, but the old-kernel workaround removes real network-policy enforcement. Do not treat that workaround as a finished daily-use solution. Lineage 21 / Android 14 also retains VNDK 30, but no exact-model or Go 7 21.0 tree was found in the inspected source set; it is another porting project, not a ready fallback. [Lineage 24 manifest](https://github.com/LineageOS/android/blob/e4b71068f6ee045ff30e4865a8d82f4047eb78ea/default.xml), [Lineage 21 manifest](https://github.com/LineageOS/android/blob/121f4ec5f11dc98ff2c427bc9d23165e914c54bb/default.xml), [network workaround](https://github.com/go7-lineage/android_device_onyx_Go7/blob/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/patches/bpfless/packages_modules_Connectivity/0003-Run-without-networking-eBPF-on-pre-5.10-kernels.patch).

## Build and compatibility facts

- The device build forces **stock kernel + stock DTB/DTBO + stock modules**, header version 2, 4 KiB pages, ARM64 plus ARM32 apps, 300 dpi, A/B, dynamic partitions and a 6 GiB super partition. The Fairphone SM7225 kernel dependency is explicitly used only for headers. The separate `go7-lineage/android_kernel_onyx_sm7225` repository is **not** selected by this BoardConfig; substituting it would be a new kernel bring-up. [BoardConfig](https://github.com/go7-lineage/android_device_onyx_Go7/blob/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/BoardConfig.mk), [dependency](https://github.com/go7-lineage/android_device_onyx_Go7/blob/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/lineage.dependencies).
- The only declared device dependency is `LineageOS/android_kernel_fairphone_sm7225` → `kernel/fairphone/sm7225`; its 24.0 head was `c84d6a30f30eb964cdf6db6981c5e77ad7591f9d`. A real local manifest must additionally supply device, exact-model vendor, E Ink and frontlight projects. CAF/display/sepolicy/Qualcomm platform dependencies are in Lineage's manifest/snippet; dependency closure still needs a real build-host check. [Kernel branch](https://api.github.com/repos/LineageOS/android_kernel_fairphone_sm7225/branches/lineage-24.0), [Lineage snippet](https://github.com/LineageOS/android/blob/e4b71068f6ee045ff30e4865a8d82f4047eb78ea/snippets/lineage.xml), [shim integration](https://github.com/go7-lineage/eink-shim/blob/70e894fd48e0a2c27e94ca6555235fc792eb91b5/README.md), [frontlight integration](https://github.com/go7-lineage/frontlightd/blob/bf015ab79a2be0711641b43757e13c32cd053d1f/README.md).
- The product is `lineage_Go7` / `Go7`, 1264×1680. There is no `GoColor7_2` product or published end-to-end color build recipe in this tree. The README gives specifications, not an install guide. [Product](https://github.com/go7-lineage/android_device_onyx_Go7/blob/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/lineage_Go7.mk), [README](https://github.com/go7-lineage/android_device_onyx_Go7/blob/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/README.md).
- `device.mk` disables OTA VINTF kernel requirements because stock 4.19.157 is below the tree's stated 4.19.325 requirement. It rebuilds vendor using selected stock blobs plus current HAL implementations; this is **not simply retaining the complete stock vendor image**. It declares shipping API 30 and a target-level 7 manifest. Copying those values cannot establish the color vendor's VINTF/SELinux/linker compatibility. [Device makefile](https://github.com/go7-lineage/android_device_onyx_Go7/blob/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/device.mk), [manifest](https://github.com/go7-lineage/android_device_onyx_Go7/blob/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/manifest.xml), [AOSP compatibility matrices](https://source.android.com/docs/core/architecture/vintf/comp-matrices).
- A stock-vendor GSI experiment is a different path: ARM64, Treble, actual cross-version linker isolation, HAL/matrix compatibility and recovery must be checked. `ro.treble.enabled=true` alone is insufficient. Lineage 24's manifest contains VNDK snapshots **31–34**, not 30; a stock VNDK 30 vendor cannot be assumed supported just by choosing ARM64. AOSP retains older VNDK APEX support for old vendor images, but the selected tree must actually supply what its binaries require. [Android GSI prerequisites](https://developer.android.com/topic/generic-system-image), [Lineage 24 manifest](https://github.com/LineageOS/android/blob/e4b71068f6ee045ff30e4865a8d82f4047eb78ea/default.xml), [VNDK deprecation exceptions](https://source.android.com/docs/core/architecture/vndk).
- A supported current full build host is x86-64 Linux; Google lists 400 GB free disk and 64 GB RAM. This Mac can do source/asset preparation; a full build has not been scheduled or run. [AOSP host requirements](https://source.android.com/docs/setup/start/requirements).

### Framework patches: static check passed; runtime behavior remains unverified

All **13 patches** passed sequential `git apply --check` against fetched, pinned upstream files. Successful patches were applied only to disposable snippets so later dependent patches could be checked. This verifies patch context, **not compilation, correct API use, security equivalence or device boot**. Evidence: [static preflight result](../.local/lineage-source-review/patch-preflight-result.json).

## Required color-model changes

These are grounded adaptation tasks, **not a claim that each is solved**:

1. Create a separate `GoColor7_2` product/vendor/device identity and paths. Preserve measured 1264×1680/300 dpi initially. Do not rename a Go7 image and reuse its binaries. [Go7 product identity](https://github.com/go7-lineage/android_device_onyx_Go7/blob/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/lineage_Go7.mk).
2. Replace every stock prebuilt with a matched exact-model asset or prove identity offline: kernel, DTB, DTBO, loadable modules, firmware, display/composer stack, waveform and relevant init/input/audio/frontlight configuration. Keep module/kernel ABI together. The public extraction script changes composer dependencies and adds Widevine/libcrypto and tinyxml compatibility fixups; review those against the exact color blobs rather than patching blindly. [Prebuilts](https://github.com/go7-lineage/android_device_onyx_Go7/tree/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/prebuilts), [extraction fixups](https://github.com/go7-lineage/android_device_onyx_Go7/blob/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/extract-files.py), [waveform definition](https://github.com/go7-lineage/android_device_onyx_Go7/blob/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/proprietary-files.txt#L475).
3. Adapt and verify the **color refresh ABI and waveform selection**. Current shim geometry is fixed at 1264×1680. It retains linear AB24/XB24/AR24/XR24 buffers, so **this audit did not find an explicit RGB-to-grayscale conversion in the Rust source**. Nevertheless, it selects A2 with Y1 dithering by default, GC16 and Regal modes; no color-panel model, color waveform choice or color-specific refresh policy is implemented. Four color channels in a buffer do not prove correct Kaleido output. Determine whether the color stock composer/kernel converts RGB, how color/full/partial modes are requested, and whether alignment/stride/rotation differ before enabling this shim. [Geometry](https://github.com/go7-lineage/eink-shim/blob/70e894fd48e0a2c27e94ca6555235fc792eb91b5/src/panel.rs), [formats](https://github.com/go7-lineage/eink-shim/blob/70e894fd48e0a2c27e94ca6555235fc792eb91b5/src/formats.rs), [refresh modes](https://github.com/go7-lineage/eink-shim/blob/70e894fd48e0a2c27e94ca6555235fc792eb91b5/src/modes.rs), [kernel ABI](https://github.com/go7-lineage/eink-shim/blob/70e894fd48e0a2c27e94ca6555235fc792eb91b5/src/abi.rs).
4. Verify frontlight topology/calibration before adopting the daemon. It forcibly claims `/dev/i2c-3`, LM3630A address `0x38`, and writes registers 0x03–0x06; it also kicks the stock `onyx_bl_br` path. Existing `onyx_bl_br`/`onyx_bl_ct` nodes alone do not prove the direct I²C path or calibration is correct. The initial color port should prefer the exact stock interface where possible. [I²C code](https://github.com/go7-lineage/frontlightd/blob/bf015ab79a2be0711641b43757e13c32cd053d1f/src/i2c.rs), [settings](https://github.com/go7-lineage/frontlightd/blob/bf015ab79a2be0711641b43757e13c32cd053d1f/src/settings.rs), [daemon](https://github.com/go7-lineage/frontlightd/blob/bf015ab79a2be0711641b43757e13c32cd053d1f/src/main.rs).
5. Reconcile exact-model VINTF, vendor ELF dependencies, SELinux and input/init behavior. Go7 init hardcodes touch reset at `...i2c-2/2-0055/reset` and removes stock services; those choices need color hardware evidence. Recovery/off-mode charging display support is explicitly uncertain in that init file. Preserve real stock security-patch/rollback metadata; the Go7 BoardConfig's September 2026 values do not establish newer kernel/vendor patches on an April stock binary. [Init](https://github.com/go7-lineage/android_device_onyx_Go7/blob/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/init/init.onyx.rc), [BoardConfig patch/AVB settings](https://github.com/go7-lineage/android_device_onyx_Go7/blob/a446be505809e1ad8bc99814bc6e8b3bfd37ca10/BoardConfig.mk).

## What exists now, and what cannot be validated offline

**Usable preparation artifacts:** pinned reference clones; exact static patch results; known product/partition/interface assumptions; the separately validated exact stock OTA and extracted-image hash evidence. They support a porting project, not a flash approval. [Stock firmware validation](stock-firmware-validation-2026-11-11.json).

**Hard blockers to an installable claim:** no exact-model product/build output; unresolved color refresh and waveform path; no demonstrated exact-build kernel/vendor/HAL/linker closure; the 24.0 BPF network-policy regression; no supported full build host selected; no tested boot/recovery path for the proposed custom output. A static build or matching kernel hash would still leave display, touch/buttons/stylus, Wi-Fi/Bluetooth/audio, frontlight, sleep/wake, encryption, charging and rollback behavior unproven.

Physical acceptance must include the four actual apps, not only APK installation: **Kindle** sign-in/download/offline reading; **Libby** library sign-in/borrow/download/offline reading and audio if used; **Audible** sign-in/download/offline playback, screen-off playback and Bluetooth; **KOReader** file access, rendering and page buttons. Android 13 already exceeds the currently stated Kindle 10+, Libby 7.1+ and Audible 9+ minimums, so those requirements do not by themselves justify Android 17. KOReader supplies an Android installation route. Minimum OS support does not certify a custom build, DRM/account behavior, app distribution, or panel performance. [Amazon requirements](https://digprjsurvey.amazon.com/csad/help/node/G4EK5XQ6BCSPSV44), [Libby requirements](https://help.libbyapp.com/en-us/6105.htm), [Audible requirements](https://help.audible.com/s/article/devices-compatible-with-audible?language=en_US), [KOReader Android guide](https://github.com/koreader/koreader/wiki/Installation-on-Android-devices).

The exact-model-named `cloudrumbles/boox-gocolor7-linux` remains a **separate Linux kernel lead**, pinned `d225defaaf94087450df626b50fc7e7522825922` on `main`, with Makefile version 6.18.40 and an empty releases API. Its inspected Qualcomm DTS directory did not contain a BOOX-named board file. None of that establishes an Android build target, userspace, installation package or compatibility with the four Android apps. Do not substitute it for the stock 4.19 kernel in this Android port without a separate kernel bring-up. [Kernel Makefile](https://github.com/cloudrumbles/boox-gocolor7-linux/blob/d225defaaf94087450df626b50fc7e7522825922/Makefile), [DTS directory](https://github.com/cloudrumbles/boox-gocolor7-linux/tree/d225defaaf94087450df626b50fc7e7522825922/arch/arm64/boot/dts/qcom), [releases](https://api.github.com/repos/cloudrumbles/boox-gocolor7-linux/releases).
