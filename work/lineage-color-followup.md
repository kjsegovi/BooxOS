# GoColor7_2 source follow-up: forks and stock-vendor baseline

Checked **2026-11-11**. Primary public source and already-extracted stock data only; no device access, downloaded-source execution, full source sync, or build. This follow-up refines the provisional version recommendation in [the first audit](lineage-color-port-audit.md).

## Decision supported by this review

**Evaluate LineageOS 21 / Android 14 with the exact stock kernel, vendor and ODM first; retain LineageOS 20 / Android 13 as the lower-delta fallback.** Neither is a build-ready GoColor7_2 target. Source inspection now establishes that 21 retains a legacy FCM 5 / 4.19 path, VNDK 30 support and real BPF implementations. The exact stock kernel has the principal required BPF configuration flags. Thus the Go7 24.0 port's disabling of BPF enforcement is **not evidence that 21 needs that workaround**. [21 FCM build definitions](https://github.com/LineageOS/android_hardware_interfaces/blob/86bf68eef83301a7f0be2a6bc460c14f36e522ac/compatibility_matrices/Android.bp), [21 GSI VNDK list](https://github.com/LineageOS/android_build/blob/bc95152efc6a43f3b103b1848c946e9bf8d4e493/target/product/gsi_release.mk), [stock kernel configuration evidence](stock-kernel-config-inspection-2026-11-11.json).

| Baseline | Source-supported advantages | Material limits |
| --- | --- | --- |
| **21 / Android 14** | Legacy FCM 5, VNDK 30; Android U BPF loader supports older kernels; official project policy still merges complete Google bulletins for 21+. | New exact-model framework/product target required; actual BPF load/attach, vendor dependencies, policy and color operation untested. Current Rust shim cannot compile unchanged with its toolchain. |
| **20 / Android 13** | Closest framework version to stock; VNDK 30; build system explicitly supports prebuilt vendor/ODM. | Best-effort backports rather than an attestable current Google patch set; no existing color target; Rust integration also blocked. |
| **24 / Android 17** | Existing monochrome Go7 source and patches. | Color adaptation still absent; old-kernel patch replaces BPF maps and loses firewall enforcement. Official 23.2/24 kernel policy expects full eBPF backports. |

## Stock vendor is supported by the build machinery; rebuilding it is not mandatory

Both inspected 20 and 21 build configurations explicitly recognize `BOARD_PREBUILT_VENDORIMAGE` and `BOARD_PREBUILT_ODMIMAGE`, suppress their image rebuild, and support separate vendor/ODM output paths. Lineage 20's Makefile copies these images into output/target files. This establishes an implementation route, **not a complete product definition or runtime compatibility**. [20 BoardConfig logic](https://github.com/LineageOS/android_build/blob/f3bb11d8739b84a311a40a3069dc4cfca688be22/core/board_config.mk#L689), [20 image copying](https://github.com/LineageOS/android_build/blob/f3bb11d8739b84a311a40a3069dc4cfca688be22/core/Makefile#L3601), [21 BoardConfig logic](https://github.com/LineageOS/android_build/blob/bc95152efc6a43f3b103b1848c946e9bf8d4e493/core/board_config.mk#L671).

Concrete settings available for a **draft device-shaped bootstrap**, subject to full configuration review:

| Setting | Intended role |
| --- | --- |
| `BOARD_PREBUILT_VENDORIMAGE`, `BOARD_PREBUILT_ODMIMAGE` | Point to matched complete stock images. |
| `TARGET_COPY_OUT_VENDOR := vendor`, `TARGET_COPY_OUT_ODM := odm` | Preserve separate partition layout. |
| `PRODUCT_BUILD_VENDOR_IMAGE := false`, `PRODUCT_BUILD_ODM_IMAGE := false` | Explicitly avoid rebuilding these partitions. |
| `PRODUCT_EXTRA_VNDK_VERSIONS += 30` | Supply the framework-side libraries requested by stock VNDK 30. Both GSI branches include 30. |
| `BOARD_PREBUILT_BOOTIMAGE` / `TARGET_NO_KERNEL` | Supported prebuilt-boot/no-kernel-build path; decide separately whether preserving full stock boot is compatible with the new system. |
| First/shipping API **30**, vendor/kernel FCM **5** | Preserve actual legacy identity rather than importing Go7's target-level 7 manifest. |

Sources: build files above; [20 prebuilt boot logic](https://github.com/LineageOS/android_build/blob/f3bb11d8739b84a311a40a3069dc4cfca688be22/core/board_config.mk#L455), [20 GSI settings](https://github.com/LineageOS/android_build/blob/f3bb11d8739b84a311a40a3069dc4cfca688be22/target/product/gsi_release.mk), [21 GSI settings](https://github.com/LineageOS/android_build/blob/bc95152efc6a43f3b103b1848c946e9bf8d4e493/target/product/gsi_release.mk), [stock metadata](stock-porting-inputs-2026-11-11.json).

Do not import Go7's source-built vendor HAL packages or composer dependency edits into this stock-vendor variant. A generic GSI instead combines product/system_ext into system and uses generic initialization; a device-shaped target can replace all three framework partitions together. Those layouts are different and require deliberate handling of leftover stock framework code. Merely setting the prebuilt macros does not inject new files into an immutable vendor image. Also, 21's `KEEP_VNDK` logic can clear `BOARD_VNDK_VERSION`; do not assume setting that variable to 30 alone supplies compatibility. Its published GSI explicitly adds old VNDK snapshots separately. [21 GSI layout](https://github.com/LineageOS/android_build/blob/bc95152efc6a43f3b103b1848c946e9bf8d4e493/target/board/BoardConfigGsiCommon.mk), [21 VNDK cleanup](https://github.com/LineageOS/android_build/blob/bc95152efc6a43f3b103b1848c946e9bf8d4e493/core/config.mk#L1282).

## Legacy HAL and kernel checks for 21

Exact stock metadata reports vendor/kernel target-level **5**, SELinux policy **30.0**, vendor NDK **30**, first API **30**, audio/effects **6.0**, Bluetooth **1.0**, gatekeeper **1.0**, and keymaster **4.1**. Lineage 21 still packages FCM 5 and accepts these legacy HAL versions; its graphics matrix accepts HIDL composer **2.1–2.4**, allocator **2/3/4**, and mapper **2.1/3/4**. Therefore Android 14 does not universally require replacing those services with the newest AIDL implementations. Full stock manifest fragments, Qualcomm extensions, ELF dependencies and framework-side service requirements still need reconciliation. [Extracted vendor manifest](../.local/porting-inputs/stock-static/vendor/etc/vintf/manifest.xml), [device matrix](../.local/porting-inputs/stock-static/vendor/etc/vintf/compatibility_matrix.xml), [21 FCM 5](https://github.com/LineageOS/android_hardware_interfaces/blob/86bf68eef83301a7f0be2a6bc460c14f36e522ac/compatibility_matrices/compatibility_matrix.5.xml).

The 21 FCM 5 build selects `kernel_config_r_4.19`; its minimum LTS is **4.19.110**, which stock **4.19.157** exceeds. FCM 6's corresponding S baseline is **4.19.191**. Retaining the true FCM 5 avoids incorrectly imposing the newer launch matrix. It does **not** waive other framework, configuration or runtime checks. [FCM definitions](https://github.com/LineageOS/android_hardware_interfaces/blob/86bf68eef83301a7f0be2a6bc460c14f36e522ac/compatibility_matrices/Android.bp), [R floor](https://github.com/LineageOS/android_kernel_configs/blob/847bbc49ae44b9161bfafb766202b6dc4d435c17/r/android-4.19/android-base-conditional.xml), [S floor](https://github.com/LineageOS/android_kernel_configs/blob/847bbc49ae44b9161bfafb766202b6dc4d435c17/s/android-4.19/android-base-conditional.xml).

The actual stock configuration (`681af35e04773432cf9195e9cfdfcff29f5344f4b12870f74c6875ac9f7aafdb`) has `BPF`, `BPF_SYSCALL`, `BPF_JIT`, `BPF_JIT_ALWAYS_ON`, `HAVE_EBPF_JIT`, `CGROUP_BPF`, `NET_CLS_BPF`, `NETFILTER_XT_MATCH_BPF`, IPv6, SELinux, and ingress/classifier support enabled. This satisfies the principal BPF flags in the inspected R baseline. `NET_ACT_BPF` is absent; that flag alone does not prove BPF program-load failure—upstream 4.19 registers `SCHED_ACT` under `CONFIG_NET`, while the actual action-attachment path is a separate question. Do not infer tethering/TC success from this check. [Stock configuration evidence](stock-kernel-config-inspection-2026-11-11.json), [R configuration](https://github.com/LineageOS/android_kernel_configs/blob/847bbc49ae44b9161bfafb766202b6dc4d435c17/r/android-4.19/android-base.config), [upstream 4.19 BPF types](https://github.com/torvalds/linux/blob/v4.19/include/linux/bpf_types.h).

Lineage 21's loader identifies Android U's baseline as **4.14**, contains kernel-version-specific program selection, and netd contains actual 4.19 ingress/egress implementations. Remaining gates include JIT sysctl writes, correctly labeled BPF mount/pin directories, successful mandatory ELF program/map creation, verifier/helper/backport behavior, an array-map write test, and cgroup program attachment/query. `BpfHandler` requires the U cgroup root at `/sys/fs/cgroup`. These need a built output and later runtime evidence; the configuration flags alone do not prove them. No BPF enforcement bypass should be imported preemptively. [21 loader](https://github.com/LineageOS/android_packages_modules_Connectivity/blob/965d387f90f22d20c3cba4dc90fd900f2e1b7ed0/netbpfload/NetBpfLoad.cpp), [program selection](https://github.com/LineageOS/android_packages_modules_Connectivity/blob/965d387f90f22d20c3cba4dc90fd900f2e1b7ed0/netbpfload/loader.cpp), [4.19 programs](https://github.com/LineageOS/android_packages_modules_Connectivity/blob/965d387f90f22d20c3cba4dc90fd900f2e1b7ed0/bpf_progs/netd.c), [attachment checks](https://github.com/LineageOS/android_packages_modules_Connectivity/blob/965d387f90f22d20c3cba4dc90fd900f2e1b7ed0/netd/BpfHandler.cpp).

## Unresolved integration and security limits

The current shim requires **Rust 1.93 / edition 2024**; 20 defaults to **1.59**, 21 to **1.75**, both edition 2021. It cannot be added unchanged to either tree. Options are a reviewed backport of the shim or a separately cross-built Android shared library with validated ABI/dependencies, **after color ABI review**. Neither has been prepared or verified. The stock V10/V20 color overlays identify ED070KC3 at 1264×1680, but those data do not validate the monochrome refresh policy. [Shim requirements](https://github.com/go7-lineage/eink-shim/blob/70e894fd48e0a2c27e94ca6555235fc792eb91b5/Cargo.toml), [Soong module](https://github.com/go7-lineage/eink-shim/blob/70e894fd48e0a2c27e94ca6555235fc792eb91b5/Android.bp), [20 compiler](https://github.com/LineageOS/android_build_soong/blob/lineage-20.0/rust/config/global.go), [21 compiler](https://github.com/LineageOS/android_build_soong/blob/7e2be266cfde19c5e0cbc8e4ed016d5572abd4fb/rust/config/global.go), [color overlays](stock-color-hardware-facts-2026-11-11.json).

Official October 2026 policy distinguishes full Google bulletins for **21+** from continuing best-effort **20** backports without advancing its attestable SPL. Current 20 build defaults still say **2026-02-01** despite later branch activity. Current official build roster contains 22.2/23.2/24.0, not 20/21; source maintenance is separate from official device builds. The exact stock vendor reports **2025-10-01**, while stock system reports **2026-04-01**. A newer framework cannot independently patch those preserved proprietary components. Preserve truthful vendor/kernel patch metadata. [Official policy](https://github.com/LineageOS/www/blob/ca73ca067d4277d1b2cf36f4af387bb7d795b70c/_posts/blog/2026-10-11-Changelog-32.md), [20 SPL default](https://github.com/LineageOS/android_build/blob/f3bb11d8739b84a311a40a3069dc4cfca688be22/core/version_defaults.mk#L100), [official roster](https://github.com/LineageOS/hudson/blob/main/lineage-build-targets), [stock vendor properties](../.local/porting-inputs/stock-static/vendor/build.prop), [stock system properties](../.local/porting-inputs/stock-static/system/system/build.prop).

**Readiness remains source-feasibility only.** Exact color rendering/refresh, stock-composer framework dependencies, SELinux mapping, all VINTF fragments, AVB/partition packaging, recovery, and required-app workflows remain unverified. Prebuilt images can also skip portions of normal build-time VINTF checking; explicit compatibility checks against extracted metadata are necessary, not an assumption that a successful packaging step tested them. [20 VINTF check conditions](https://github.com/LineageOS/android_build/blob/f3bb11d8739b84a311a40a3069dc4cfca688be22/core/Makefile#L4833).

## Local compiler and binary follow-through — 2026-11-11

The parent prepared a local Rust1.75/edition2021 adaptation under `components/eink-shim`, preserving upstream refresh values and hardware paths. Its 69 existing unit tests passed with the manifest-selected Android Rust compiler; ARM64 API30 type checking and a shared-library link against official verified NDK public stubs passed. See `eink-rust175-compatibility-2026-11-11.json`. This resolves the compiler mismatch for the isolated component, not full Soong/product/vendor integration or color behavior. No candidate image exists.

Exact stock Color kernel Image SHA256 `6b82120059c7e7fe65c36d4c18d792ccf23262a559e91dac6b57e624a6e59334` matches the pinned Go7 reference prebuilt byte-for-byte (60,735,504 bytes). The exact stock Color display-service `.text` and `.rodata` bytes match the public Go7 vendor prebuilt; dynamic metadata differs. See `color-composer-reference-comparison-2026-11-11.json`. This supports a shared display-service implementation and kernel update ABI. It does not establish correct color waveforms, framework metadata, calibration, panel routing or hardware output. The exact color DTB/DTBO and stock configuration must remain the inputs.

The shim’s inherited `vendor: true` module plus composer loading fixup would require a reviewed derivative stock-vendor image or another qualified loader design. A byte-identical vendor image cannot simultaneously acquire a new file/ELF dependency. Keep this distinction explicit before implementing the full product.
